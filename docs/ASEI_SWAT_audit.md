# ASEI 实现与 SWAT 运行审计

## 依据与结论范围

方法验收依据为工作区的 [In1_1_4.md](../../In1_1_4.md) 和 [impl.md](../../impl.md)。运行证据为用户提供的 [训练日志](../../asei_swat_label_seed42.log) 和 [16项指标报告](../../test_report.1793159611.user.3901340.csv.csv)，对应实现 `asei-finite-bank-scan-3.1`、PyTorch 2.4.1+cu121、seed=42、SWAT。

早期比较依据为提交 `393d211` 的代码和文档。当前工作区没有 In1_1_3.md，故不宣称已经逐字核验缺失的旧稿。对照早期实现，当前版本包含方法与预算变更，不能称为仅做计算或多卡并行的等价加速版。这些主要变更由最新方案明确规定。

本地没有 SWAT 原始数据及服务器 checkpoint。下面把已验证的实现问题、日志事实、算术推断和待服务器验证的原因分别列出，不将 CPU 小样本结果当作检测效果提升证据。

## 1. 最新方案的实现核对

| 内容 | 核对结果 |
|---|---|
| 官方训练/测试边界 | TAB 按 train_lens 切分；ASEI 不把测试输入送入拟合 |
| F/Cfit/Rref/Vsel/Vcal | 官方训练495000点分为316800/39600/39600/49500/49500，符合方案 |
| 预处理 | 统计量只从 F 估计、分段因果填充；发现十进制常量列判断错误，已按“常量尺度1”修复 |
| 编码器及图 | 通道共享残差 DWConv→LayerNorm→Linear→GELU，W=63；正滞后、稀疏邻域、先汇集后投影 |
| 连续目标块 | 每轮完整覆盖 [H,N_F)，保留尾块；固定权重下与逐点窗口的预测、Huber损失和梯度通过独立核验 |
| 校正器 | s=max(mean(d),IQR(d),1e-4)，y=d/s；beta L1≤0.95；共享MLP；先线性后补偿，r=s(y−y_hat) |
| 独立参考 | Rref自身预热，使用全部对齐d/r；FP32排序、左插入尾部、先合并分支后中心化 |
| 索引 | H=78，参考首索引82，评分首索引89；参考不额外删除R−1点 |
| 门控和递推 | 两路证据顺序为校正/状态；8个可学习标量；带符号a读出；lambda/kappa范围及初始化符合方案 |
| 并行扫描 | 倍增前向及明确一阶反向；零点和通道并列口径、末态梯度、跨块梯度均有顺序参考核验 |
| 辅助任务 | 384训练对、48验证对，三族×两布局均衡；观测空间扰动、有效性重采样、固定种子、有限证据缓存 |
| 辅助损失 | 先逐任务计算事件均衡正例、加权负例和固定点对排序，再对任务等权；验证六组等权 |
| 阈值 | 只用Vcal，h=sort(S)[N−floor(alpha N)−1]，严格S>h，不限制负阈值 |
| 流式与指标 | 保持原时间长度，首89点不报警，分块不重置状态；沿用TAB全部16项label和6项score指标 |

当前并行化发生在单卡内的块、通道和张量运算。跨卡 DataParallel 路径按后续单卡要求移除。数学等价测试验证的是相同权重、目标集合和损失定义；不同有效批量、优化器或训练预算不会自动产生相同的训练权重。

## 2. 相对早期实现的设计与预算差异

| 内容 | 早期实现 | 最新方案 |
|---|---|---|
| 时间编码 | 普通全通道隐藏卷积 | 残差深度卷积及隐藏维线性混合 |
| 图统计 | 全部对齐时刻 | 最多65536个确定性原始时间锚点 |
| 预测器批量 | 每步最多128个目标 | SWAT每步8块×256=2048个目标，尾批可较小 |
| 预测器预算 | 最多50轮、patience=5 | 最多20轮、至少5轮、patience=4 |
| 校正 | 原误差量纲，FP64全批量投影回溯，最多1000次；MLP按轮训练 | 归一化误差，FP32 Adam，两阶段各100次更新 |
| 评分器 | 六组固定kappa/ranking权重候选，30轮与固定检查点 | 一个联合学习lambda/kappa的评分器，最多10轮 |
| 辅助任务 | 每轮重新生成128对；短/长/密集/再发场景 | 固定384对训练库和48对验证库；单事件/双事件布局 |
| SWAT辅助前后缀 | 640次正常前缀更新、768点恢复后缀 | 128次前缀更新、121点恢复后缀 |
| 正常验证 | 99000点兼用于选择和校准 | 独立49500点Vsel和49500点Vcal |

这些差异会改变函数容量、优化轨迹、辅助覆盖或验证分布。图统计上限属于方案明确规定的近似统计；它没有删除预测器的训练目标。前向时间块复用、冻结证据缓存和扫描则属于计算组织优化，应分别验证数值及梯度等价。

以相同316722个F预测目标核算，早期每步128个单点目标需2475次更新/轮；当前每步最多2048个目标需155次更新/轮。即使每轮都访问全部目标，较大有效批量和较少更新仍会改变训练轨迹。速度提升还包含这些预算与批量因素，不能全部归因于并行运算。

## 3. SWAT 数据覆盖核算

| 片段/任务 | 原始长度 | 实际有效量与访问方式 |
|---|---:|---|
| F | 316800 | 每轮316722个预测目标；155批；18轮共5700996次目标访问 |
| Vsel正常预测验证 | 49500 | 每轮49422个预测目标；25批；18轮共889596次目标访问 |
| Cfit | 39600 | 39518个校正目标；每阶段100步、批量至多2048、保留尾批；算术上恰为5个完整遍历、197590次访问 |
| Rref | 39600 | 39518个完整d/r参考点，全部保存 |
| Vcal | 49500 | 49411个就绪分数，全部用于阈值 |
| 训练证据库 | 384对 | 10轮中每轮完整访问；按长度分桶后50批，共500次更新 |
| 固定辅助验证库 | 48对 | 每轮完整评估；六组各8对，等权汇总 |
| 图结构统计 | 316784个候选原始时刻 | 按最新方案取65536锚点，不缩短原始时间轴 |

原始历史仅用来预热，不是为了加速而删掉真实目标。单批尾部的张量补齐由mask排除，不丢弃真实尾目标。完整目标索引测试直接验证316800点F和49500点Vsel的DataLoader中，每个有效目标恰好出现一次；校正索引测试验证SWAT两阶段各恰好完整遍历5次。

“使用全部验证数据”须区分用途：正常预测早停使用Vsel全部有效目标，阈值使用Vcal全部就绪分数；评分器按方案只使用48个固定扰动任务，不将Vsel全部时刻都放入辅助损失。日志的2次正常证据遍历、432次扰动证据构建及评分训练0次提取器调用与该流程相符。

对实际服务器数据的逐值、列映射和预测时间对齐核验，仍需原始CSV及checkpoint。新增覆盖计数与断言将这些数量写入日志和checkpoint，便于直接复核，避免只根据进度条推断。

连续性范围须单独说明：当前每个TAB文件按一个连续实体处理，模型没有自动识别文件内部真实断点。若文件实际拼接了多个实体或有已知断点，不能直接把总行数当作最长连续长度，须提供连续段定义后适配；现有日志不能证明SWAT是否含此类断点。诊断脚本分别报告原始训练/测试时间戳的重复、非递增和不等步长数量，但不根据时间抖动猜测实体边界。

## 4. 从日志和结果可以得到的结论

- 预测器最优为第14轮，Vsel Huber=0.01914982；第15至18轮连续未改善后停止，符合patience=4。
- 评分器验证损失从64.106062降至49.002122；10轮持续下降，最终模型在预算末端。不能据此认定已收敛，值得用Vsel比较更长预算。
- 最终lambda≈0.877622、kappa≈0.027109。仅凭这两个值不能判定门控或校正器工作正常，须查看训练偏置、损失分量和通道证据。
- 校准N=49411，K=494，h=37.3153076171875，实际严格超阈412点，即0.833822%。相同阈值的并列分数允许实际计数少于K，现有计数符合定义。
- 测试precision=0.1337014、recall=0.9332857、F1=0.2338952、accuracy=0.2577731，主要表现为误报过多。

由同一二分类样本集的accuracy/precision/recall反推，预测异常比例约84.7430%，正常点误报率约83.5567%，异常比例约12.1402%。这些是指标算术推断，并非读取原始混淆矩阵。校准的1%经验运行点不保证测试分布也有1%误报；方案本身也未作该保证。

可以确认的事实是校准段和测试结果之间存在明显运行点差异。常量列错误、正常工况覆盖差异、参考分布转移、合成任务与实际故障的差异、评分训练预算不足、GPU并列值数值敏感性均需区分；现有日志不能唯一确定其占比。

## 5. 已修复问题及验证边界

### 十进制常量列

先前代码以浮点`std==0`识别常量。316800行恒定0.3和7.2的两列，在FP64的axis-0归约中分别得到约1.73e−12、1.52e−11的非零标准差，导致尺度错误、标准化结果为−1和+1。常量列稍微变化即可被放大成巨大的标准化偏移。

当前按填充后实际值是否完全相同识别常量，并把其均值设为常量本身、尺度设为1。真正非零的小方差保留原Z-score尺度，没有加入任意尺度下限、移除常量通道或更改尾部比较。旧checkpoint的统计量保持原样以便复现；修复后的训练需要重新拟合模型及参考。

### 覆盖与诊断

增加了每轮目标覆盖断言、校正样本访问计数、评分器每轮全部任务恰好一次的断言，以及判别/排序损失分解。训练公式、学习率、默认轮数、数据划分、alpha和全部TAB指标保持最新方案的设置。checkpoint文件名的摘要包含实现版本，避免相同数据和超参数的新实现覆盖旧模型。

单独的常量通道CPU探针检查了3个种子：缓存切片证据最大差为0，整段与逐点评分最大差不超过9.54e−7，报警无差异。独立FP64测试还核对了逐点/连续块Huber损失及参数和输入梯度。它们支持计算路径的一致性，不证明SWAT效果改善。

PyTorch不保证批量/切片运算逐位相同；ECDF的严格相等在大量重复值附近可能放大微小误差。因此提供部署GPU上的冻结数值探针，不通过给尾部加epsilon或更改排序定义掩盖问题。依据见 [PyTorch 2.4.1数值精度说明](https://github.com/pytorch/pytorch/blob/v2.4.1/docs/source/notes/numerical_accuracy.rst)。

## 6. 无重训练的服务器诊断

同步当前代码后，在TAB根目录运行：

```bash
uv run python -B scripts/audit_asei.py \
  --checkpoint result/asei_checkpoints/SWAT_label_seed42/asei_seed42_d1f3f4e3308c6810_577d22b5.pt \
  --data-name SWAT.csv \
  --include-test \
  --device auto \
  --gpus 1 \
  --output result/asei_audit/SWAT_seed42.json
```

脚本先核验训练数据值和列顺序的SHA256，使用保存的预处理、参考和阈值，从零状态分别分析F/Cfit/Rref/Vsel/Vcal与测试段。输出常量尺度违规、原始/残差超参考最大值比例、证据饱和比例、主导报警通道、分数分位数、Vcal重现差异、GPU分块/批量数值差异及测试混淆矩阵。训练标签只用于事后检查正常数据假设，测试标签只用于事后统计；不训练、选参、更新阈值或覆盖checkpoint。

真实日志与报表的本地解析记录见 [ASEI_SWAT_audit.json](ASEI_SWAT_audit.json)。静态解析没有伪造原始SWAT数值诊断结果。

## 7. 后续优化的优先顺序

1. 先审计旧checkpoint，再以相同最新方案默认预算重训修复后的版本。输出目录与历史运行分开，记录版本和种子。常量列修复是否改善SWAT，需要真实重跑验证。
2. 若评分器在预算末端仍明显改善，保持预测器、校正器、参考、任务清单与alpha不变，仅在Vsel上比较20/50/100轮等更长评分预算。该实验明确属于训练预算变更，不能混记为默认10轮主方法或纯计算加速。
3. 同时检查正常工况与参考覆盖：对比Rref、Vsel、Vcal及测试中事后正常点的证据和主导通道。若需要调整参考窗口、划分、阈值或通道处理，应作为方法/协议变更单独确认和记录。
4. 训练采样中`hard=index%2`与双子类型`subtype=index%2`完全绑定，虽然各自边际数量均衡，却缺少交叉组合。可以设计独立平衡分配的对照实验；本次没有改动任务生成规则，以保留现有方案和任务复现。
5. 配合原TAB score配置检查全部6项连续分数指标，区分排序能力差与固定阈值迁移差。测试指标只用于报告，不据此挑选alpha或检查点。

若与当前仓库的AnomalyTransformer标签结果比较，还须记录运行点：其默认anomaly_ratio包含10个百分比，而ASEI默认只有alpha=0.01这一个点。两者都从各自验证数据估计阈值，但同一组指标并不代表同一运行点，不能把多运行点聚合结果直接解释为与固定1%协议的等条件比较。代码依据见 [AnomalyTransformer.py](../ts_benchmark/baselines/self_impl/Anomaly_trans/AnomalyTransformer.py)。

当前不宣称已解决真实SWAT误报，不将CPU小样本效果当作优化收益，也没有为了取得更高测试F1修改alpha、读取测试数据拟合参考或扩大默认训练预算。
