# DynamicNeighborhoodStat 性能优化候选

依据：[In1_5.md](../../In1_5.md)、TAB 当前源码，以及本地 CPU 算子记录。本文给出供选择的优化点，不包含对应的模型实现。候选方案的 GPU 加速幅度与检测指标均待测；乘加次数分析不等于实际加速比例。

## 设计机制与优化边界

方案的核心是重构任务及其信息约束。邻域路径用其他变量的多尺度水平、变化观测重构目标变量的粗指标；尺度权重依赖目标—来源组合，邻域权重随窗口变化。自身路径用目标片段之前的历史预测去趋势后的 A/C/J，以末点预测补充即时证据。两条路径在相同跨度上分别刻画局部背景与剩余波动，避免把不可预测的随机取值完全当作异常。

自身统计的正常能量范围约束用于限制异常历史引起的外推。正常验证确定的邻域支持标志、误差尺度和固定阈值用于评分。上述机制比 TCN 的具体深度、实现时的张量拼接方式更接近方法贡献本身。

优化需要保留以下条件：

1. 邻域预测不依赖目标变量自身观测；归一化和共享编码也不能把目标信息传入其他来源。
2. 统计头只能看到截至 t-h 的自身历史，末点头只能看到截至 t-1 的历史；当前片段的均值、趋势、残差及统计量仅进入目标构造。
3. 六个候选尺度、目标相关的动态尺度权重、全部非自环来源的归一化和反集中正则继续成立。
4. A/C/J 目标、正常能量预测范围、近常量坐标规则、训练方差及验证误差校准保留。
5. 训练/验证独立构窗，测试逐点右对齐，保持前缀无效区间和真实事件评价规则。

当前已经使用粗指标累积和、跨目标复用来源编码、变量折叠进批维、同一次自身编码的多位置读出、目标分块和梯度重计算。这些不再列为新的优化点。已有 cuDNN 修复属于比较基线的一部分。

## A 类：保留模型定义的实现优化

数学等价不代表不同算子、不同编译器下浮点结果逐位相同。涉及 Dropout 的执行图优化也可能改变随机数消耗顺序，需要在关闭 Dropout 或固定掩码时比较前向和梯度。

### A1：拆分路由首层仿射投影

当前 `_route()` 为每个目标—来源—尺度组合拼接输入，再通过 MLP。对首层可以使用恒等式：

\[
W[e_i;e_j;e_m;H_{j,m};c_{-i}]+b
=W_i e_i+W_j e_j+W_m e_m+W_H H_{j,m}+W_c c_{-i}+b.
\]

来源项按 j、m 计算一次，目标项按 i 计算一次，再广播相加。GELU 必须在各项相加后执行，后续线性层与两个 softmax 保持原定义。值映射、关系网络、解码器及编码器输入投影也可按各自可复用的项拆分。

这借鉴 AT/CATCH 的投影复用方式，但不是把原门控换成另一种注意力。全部来源和尺度仍参与归一化，也不改变目标排除。

在 B=32、d=51、K=6、MLP 隐层 64、当前输入维度下，尺度门控和值网络的两个首层投影合计约 4.602G MAC；拆分后的独立投影约 0.0436G MAC。广播求和、GELU、后续线性层和 TCN 仍需计算。整体成对路由仍有 O(d²K) 工作，不能据此声称整网加速百倍。

适用：训练、验证、校准、推理。实现工作量中等，优先级高。现有参数可以沿用，但训练时不能把可学习投影缓存到下一次优化器更新之后。

### A2：按静态依赖裁剪 TCN 计算

本项可以分别选择 A2a 或 A2b。

**A2a：短尺度的无效卷积核位置。**

核长为 3、膨胀率为 δ 的左因果卷积读取 q、q-δ、q-2δ。当输入长度 n≤δ 时，后两项始终来自零填充，卷积等价于使用当前位置对应权重的逐位置线性映射。其后 LayerNorm、GELU、Dropout 和残差连接仍按原顺序执行，仍共享原参数。

当前邻域序列长度为 32、16、8、4、2、1，膨胀率为 1、2、4、8，每个残差块两次卷积。48 次邻域卷积调用中有 20 次符合这一条件。其余部分无效的核位置也可以静态排除，但额外 gather 的收益需实测。

这里借鉴 AT 的逐位置线性计算和 ModernTCN 消除静态冗余的思想，具体等价条件来自本模型的序列长度。不能把整条短尺度 TCN 随意替换成一个浅 MLP，也不能合并中间的非线性或 LayerNorm。

适用：所有阶段。保留现有权重和表达能力；主要目标是减少零填充、无效乘法和调用开销，实际收益不能按 20/60 的调用比例估计。

**A2b：仅计算实际读出所依赖的高层位置。**

邻域编码器每尺度只读取末点。自身编码器最终只读取零基索引 95、111、126，即两个统计头和末点头；其余高层输出不参与损失或评分。可以从这些读出点沿卷积和残差连接逐层回溯，只计算真正需要的位置。

对于输出位置集合 Q，一层核长 3、膨胀率 δ 的卷积需要前层的 Q、Q-δ、Q-2δ 中非负的位置。残差分支和每层的零填充必须一并保留。负索引对应该层外部的零填充，不能错误地计算成带偏置的隐藏状态。逐位置 LayerNorm 不依赖被删去的其他时间位置，因此允许这种裁剪。

按当前网络的静态依赖集合计数，每个变量的卷积“输出位置数”如下。这里一个位置仍计算全部 32 个隐藏特征。

| 路径 | 完整计算 | 依赖裁剪后 |
|---|---:|---:|
| 六尺度邻域合计 | 504 | 186 |
| 自身三读出合计 | 1524 | 600 |
| 合计 | 2028 | 786 |

这是卷积输出位置的理论计数，约减少 61%，没有改变任何读出点的历史依赖或感受野。完整等价性仍需以前向、梯度和目标排除检查验证。Dropout 的随机数顺序可能改变，比较梯度时需关闭 Dropout 或固定相应位置的掩码。

可借鉴 TranAD 按末点需求输出的组织，但具体执行需要静态 gather 和小矩阵运算，不是直接复制其解码器。本项实现难度高于 A2a，且索引开销可能影响 GPU 收益，适合与 A5 编译一起评估。不能把“只算读出依赖”误写成只输入最后三个原始观测。

### A3：训练统计留在 GPU，减少布局复制和主机同步

当前 `_epoch()` 每批将 5 个损失项和 3 个集中度统计逐一转换为 Python float；CUDA 执行时会形成多次主机同步。可在 GPU 上用 detach 后的累加量记录整轮统计，只在进度输出和轮末拷回。非有限损失与梯度检查保留，不用取消检查来换速度。

同时将标准化序列一次整理为连续布局，使用批量窗口索引和有界预取，避免先为每个 NumPy 窗口复制、再 collate 复制。CATCH/DCdetector 的批量维度组织可作参考；数据增强、样本顺序、训练 batch size 和 loss 权重不变。DataLoader worker 数需实测，不能假定越多越快。

PyTorch 官方也将逐项读取 CUDA 标量和不必要的 CPU/GPU 拷贝列为同步开销来源，见[性能调优指南](https://docs.pytorch.org/tutorials/recipes/recipes/tuning_guide.html#avoid-unnecessary-cpu-gpu-synchronization)。

适用：训练为主，也改善验证与推理统计。工作量较小，优先级高。

### A4：按固定支持标志执行推理，并分离评分与诊断

支持标志 b_i 已在正常验证集上固定。b_i=0 时，变量分数完全由自身路径给出，因此推理可以跳过该目标的邻域路由和解码。该变量仍必须保留为其他目标的来源；只减少目标行，不减少来源列。至少存在一个受支持目标时，邻域来源编码通常仍需处理全部变量；若全部 b_i=0，则可跳过整条邻域路径。

另外，Top-r 集中度、消息幅度和部分测试诊断不影响最终分数，可放在单独的完整诊断模式。GPU 上完成误差归一化、路径融合及 log-sum-exp 后，只传回最终分数和需要保存的逐变量分数；不必每批把所有 19 个误差坐标传回 CPU。

保留完整诊断模式供机制实验使用。若只计算受支持目标，不能把其集中度汇总当成全目标图诊断。训练和支持校准前仍计算完整目标集合。

适用：推理。收益取决于实际支持比例和诊断开销；不能用小样本中支持比例为 0 推断完整 SWAT 的收益。方法定义和已有检查点均可保留。

### A5：编译计算核心，并分别选择各阶段执行参数

将日志、文件读写、数据指纹和 Python 标量控制留在编译区外，对固定形状的编码、路由和损失计算评估 `torch.compile`。重点验证小算子融合和启动开销，避免图中断与反复编译。完整批次可以使用编译路径，最后不足一批仍保留，可使用单独的形状或 eager 路径。[PyTorch 编译文档](https://docs.pytorch.org/docs/stable/generated/torch.compile.html)说明编译模式及其适用限制；收益依赖服务器 PyTorch、CUDA 和硬件环境。

训练 batch size 先保持不变；离线验证、校准和批量测试可使用独立的更大 batch size。目标分块和路由重计算按峰值显存与吞吐量选择，不默认关闭重计算。本地 CPU 结果中关闭重计算没有明显收益，且目前只覆盖路由，不会消除自身 TCN 的激活存储。

在线单点检测仍需测 batch=1 延迟，不能把离线攒批后的吞吐量称为在线低延迟。编译首次启动时间和稳定运行速度分别报告，防止将编译等待误判为运行停滞。

适用：训练与推理。优先完成 A3，再评估本项。方法定义保留，但执行图、浮点顺序和随机数顺序可能不同。

### A6：缓存确定性观测，复用校准和评价结果

可按需求选择缓存范围：

- A6a：以时间端点索引粗指标和 A/C/J 目标，各集合独立计算，不缓存展开后的全部原始窗口。训练参考统计尽量复用这些确定性目标。以 19 个 float64 坐标估算，默认 SWAT 的内部训练窗口缓存约 2.86 GiB；末点可直接读取原序列，实际容量可降低。内存不足或磁盘随机访问慢时可能得不偿失。
- A6b：验证遍历时保留本轮残差及校准需要的诊断，最佳轮的缓存用于后续顺序校准，避免恢复最佳模型后再完整执行一次验证前向。默认验证误差缓存约 0.75 GiB，另有诊断；比较候选轮和最佳轮时可能需要两份缓冲。需权衡每轮传输与写盘成本。
- A6c：同一模型的标签与分数评价共用一次测试前向。当前多模式脚本虽然复用检查点，但第二个入口创建新实例，会再次推理。缓存必须同时校验模型状态、测试内容、列顺序及推理精度。只运行 label 的命令不从跨模式复用中获益。

适用：预处理、校准或重复评价，不能加速 TCN 本身。当前一次自身编码已经共用多个头，不重复列为缓存收益。

## B 类：保留创新机制，但改变架构或数值实现

### B1：精简 TCN 深度，保持所需感受野

In1_5 约束邻域感受野至少为 32，自身感受野至少为 L-1，未要求现有的具体层数。当前使用的感受野分别为 61 和 253，存在结构调整空间。

每块两次核长 3 的卷积时，R=1+4∑δ。对于 L=128，可测试下列候选：

| 路径 | 候选膨胀率 | 残差块数 | 感受野 |
|---|---|---:|---:|
| 邻域 | 1、2、5 | 3 | 33 |
| 自身 | 1、4、12、15 | 4 | 129 |

这两组配置均可形成连续的滞后覆盖。保持变量独立、左因果填充、逐位置 LayerNorm、原预测头及统计约束。一次前向卷积调用可从 60 次降为 44 次；这只是计算图计数，不代表延迟按同一比例下降。

本项不是旧权重的等价变换，需要重新训练和校准。较浅结构的拟合能力、有效感受野和正则强度可能改变。精简层数也减少 LayerNorm、GELU 和 Dropout 的执行。若另行减少 Dropout 调用，需视为训练变体；把 p 从 0.1 调到 0.05 并不会免去随机掩码计算。

适用：训练与推理。接受重训时优先于直接换成全新的骨干。

### B2：借鉴 ModernTCN，采用因果深度可分离卷积

将每个全特征时间卷积改为 hidden feature 内的 depthwise 因果卷积，再以逐位置 pointwise 混合该变量的隐藏特征。物理变量仍折叠在批维，不能像 ModernTCN 的跨变量 FFN 那样把传感器先混合起来。

以宽度 32、核长 3 为例，每个时间位置的卷积 MAC 从 3×32²=3072，变成 3×32+32²=1120，理论上降低约 64%。这不包括其他操作；两个小卷积还可能比一个完整卷积有更多调用开销，所以 GPU 延迟未必按 MAC 降低。

这种分解限制卷积核的参数化，不能声称与现有全卷积等价。保留因果填充与逐位置 LayerNorm，重新训练并校准。建议先单独比较 B1 与 B2，再考虑组合，便于判断表示能力损失来自哪里。

适用：训练与推理。结构变化比 B1 更大。

### B3：网络使用 BF16 混合精度，统计和校准维持高精度

仅对编码器与路由的卷积/线性计算考虑 BF16 autocast。去趋势能量、四阶统计、对数、能量下限、训练参考统计、误差分位数、阈值与最终评分保留现有精度。尤其不能让接近冻结状态的能量和近常量坐标完全落入低精度计算。

AMP 的能力与数值规则参考[PyTorch AMP 文档](https://docs.pytorch.org/docs/stable/amp.html)。具体可行性依赖服务器硬件；不能根据 CPU 分析承诺收益。精度变化可能改变支持标志与残差分布，需要使用实际推理精度重新校准；混合精度训练还需重新训练。即使最终评分使用 float64，也无法补回神经网络低精度计算已丢失的信息。

适用：支持相关运算的 GPU 训练和推理。创新机制保留，数值实现不等价。

## 不作为首轮优化的做法

- 直接复制 AT 的步长 100 推理，再补齐或复制分数，会改变本方案逐点末端评分和及时性，不能视为等价加速。
- 对完整序列执行一次有状态 TCN 后直接复用隐藏状态，会引入独立窗口左边界之前的观测。当前每个窗口逐层左补零，直接流式缓存不能保持同一映射。仅保留因果性也不足以证明与原有限窗口实现等价。
- 将六尺度先混成单个与目标无关的表示，再做邻域注意力，会丢失目标—来源特定的尺度选择。
- 静态 Top-k 邻居或稀疏采样来源会改变动态邻域 softmax 和反集中正则。A4 的目标行跳过不属于这种来源裁剪。
- 不直接复制 CATCH/ModernTCN 的完整窗口 RevIN、对称卷积和跨变量混合。自身统计头之前使用完整窗口归一化，即使统计量 detach，仍可能通过数值依赖看见目标片段；只查梯度不足以发现这种情况，还需扰动检查。
- 训练步长增大、减少训练轮数或固定抽取正常窗口会改变训练预算或采样分布，可以作为另行选择的训练策略，但不属于等价实现提速。
- 将所有尺度填充到最长 32 再统一计算，可减少调用，却把粗时间位置从 63 提高到 192，接近三倍；不在缺少 GPU 测量时默认采用。

## 最小验证与选择顺序

先在目标 GPU 固定 SWAT 数据版本、训练/验证边界、列顺序、L=128、随机种子与训练 batch size，对单个候选测量。已有 CPU 记录只定位可能的开销，不能充当 GPU 优化结果。

| 验证目的 | 最小检查 |
|---|---|
| A 类是否保持计算语义 | 同一检查点比较路径输出、最终分数和支持/校准量；关闭 Dropout 或固定掩码比较参数梯度；对 A4 比较完整路径与跳过目标行的分数 |
| 是否保留创新信息约束 | 扰动目标变量检查邻域输出不变；扰动目标片段检查自身统计预测不变；保留输入梯度检查与构窗边界检查 |

不需要对每个算子优化重复跑完整训练。A 类先做同权重的语义与速度对照，B 类才需要完整训练和检测质量比较。正式性能结果保留相同工作量，不能把少训练几轮形成的差异当成单批计算加速。

稳妥起点为 A1+A2a+A3+A4，保留现有架构、目标与逐点评价。如果愿意增加实现复杂度，优先单独评估 A2b，再考虑与 A5 组合；它比减少 TCN 层数更接近同一检查点的计算优化。A5 依赖服务器环境，A6 按具体重复工作和内存预算选择。如果接受重新训练，也可选择 B1；B2 与 B3分别评估，不同时叠加多个变化来判断收益。各项收益存在重叠，不能把理论降低比例直接相加或相乘。
